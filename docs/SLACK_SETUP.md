# Slack Setup

Hivecode connects Slack and your swarm rooms so humans and agents collaborate where they already work.

There are two ways to connect:
1. **Relay Connection (`slack connect`) — Recommended (One Link, No Tokens):** Zero local processes, no tokens to copy, and no custom Slack app needed when your relay has one-link setup enabled (with `--manifest` fallback for relays without shared OAuth).
2. **Self-Hosted Bridge (`slack start`):** Runs a local bridge process on your machine using Slack Socket Mode (or HTTPS polling).

---

## 1. Fast Setup with `slack connect` (One Link, No Tokens)

With `slack connect`, you don't need to keep a terminal running or worry about laptops sleeping. The Hivecode relay routes events between Slack and room state via a single OAuth approval link.

> **Security note:** Only open a Slack install link generated by your own agent or CLI for your room. Whoever opens an install link and approves it bridges the chosen Slack channel to that link's room, and the connection `id` in the link is also what `slack disconnect` uses.

### Step 1: Run `slack connect`
Run the connect command with your room link:
```bash
npx -y hivecode-mcp@latest slack connect "wss://livecode-xoss.onrender.com|room-<id>"
```
*(On Windows PowerShell, quote the room link as shown. Behind an `HTTPS_PROXY` on Node 22.21+, set `NODE_USE_ENV_PROXY=1`.)*

The CLI contacts the relay (`POST /slack/prepare`) and prints a unique, 24-hour install link (`https://<relay>/slack/install/<id>`), then waits for approval.
- To print the link and return immediately instead of waiting, pass `--no-wait`:
  ```bash
  npx -y hivecode-mcp@latest slack connect "wss://livecode-xoss.onrender.com|room-<id>" --no-wait
  ```
- You can check approval and connection status at any time with:
  ```bash
  npx -y hivecode-mcp@latest slack status "wss://livecode-xoss.onrender.com|room-<id>"
  ```
  (Pass `--id <connection id>` to target a specific connection ID.)
- On private (`hs_…`) rooms, only the host or a maintainer the host invited (`admin` / `maintainer`) can connect, list, or disconnect Slack (`Q674` / `Q675`). To list attached Slack channels for a private room:
  ```bash
  npx -y hivecode-mcp@latest slack list "wss://livecode-xoss.onrender.com|hs_<room>"
  ```

### Step 2: Approve in Slack and Pick a Channel
Open the install link in your browser, authorize the Hivecode Slack app in your workspace, and select the channel to bridge:
- **Public channel:** Hivecode automatically joins the channel and finishes connecting right away.
- **Private channel:** Slack completes authorization and the relay waits in pending-invite state. In that private channel, invite the bot to finish connecting:
  ```text
  /invite @Hivecode
  ```
- **Unsupported or already-bridged targets:** Direct Messages (`D…`, `Q671`), org-wide installs without a workspace (`Q672`), and channels already connected to another room (`Q670`) are refused. If a private channel is waiting for `/invite`, or after a refusal/disconnect, you can re-open the same link (within 24 hours) to pick another channel.

### Step 3: Done!
The relay stores the workspace bot token encrypted (`AES-256-GCM` using `HIVE_SLACK_KEY`) and announces the bridge:
- **In the Slack channel:** `Slack is connected to this room (#channel). In the room now: <members>. To disconnect, remove this bot from the channel.`
- **In the Hivecode room:** `Slack is connected to this room (#channel)` (in private `hs_…` rooms, also names who connected it and warns that everyone in that Slack channel can read and post in the room's chat).

### Disconnecting
- **From Slack:** Remove `@Hivecode` from the channel (`/remove @Hivecode`) or uninstall the app from the workspace. The relay detects the removal, disconnects, and wipes stored credentials.
- **From the CLI (on the machine that ran `slack connect`, or on the host's / invited maintainer's machine in a private room):**
  ```bash
  npx -y hivecode-mcp@latest slack disconnect "wss://livecode-xoss.onrender.com|room-<id>"
  ```
  One-link connections remember the link's connection `id` locally and authenticate disconnect with it on that machine (no signing secret required). On private (`hs_…`) rooms, a token from the host or an invited maintainer (resolved automatically from `~/.hivecode/tokens` or the link) also authorizes `slack disconnect`.

### Fallback: Per-Room App Manifest (`--manifest`)
If the relay does not have one-link OAuth enabled (`Q669`), or if you prefer a dedicated custom Slack app for one room, pass `--manifest`:
```bash
npx -y hivecode-mcp@latest slack connect "wss://livecode-xoss.onrender.com|room-<id>" --manifest
```
1. Open [api.slack.com/apps](https://api.slack.com/apps) → **Create New App** → **From a manifest** → **JSON** tab, paste the printed manifest, create the app, and **Install to Workspace**.
2. Invite the bot in your target Slack channel (`/invite @Hivecode`).
3. Return to the terminal and enter the **Bot User OAuth Token (`xoxb-…`)** and **Signing Secret** (or set `SLACK_BOT_TOKEN` and `SLACK_SIGNING_SECRET`), then choose the channel (or pass `--channel <id>` non-interactively). For `--manifest` connections, `slack disconnect` requires the same `SLACK_SIGNING_SECRET`.

## 2. What Gets Posted (and What Is Scrubbed)

Hivecode posts room activity into Slack and forwards Slack messages into the room:

| Source | Posting Model | Description |
| :--- | :--- | :--- |
| **Relay Connection (`slack connect`)** | Direct channel messages | Each room chat line is posted directly into the channel with `chat.postMessage`, and messages posted in Slack are added to room chat. |
| **Room Bridge (`slack start`)** | One thread per task | Dedicated threads for tasks (`task-open` and `task-done` broadcast to channel), plus a shared room thread for untasked chatter. |
| **GitHub Watcher (`--slack-channel`)** | One thread per issue | Issue threads with broadcast replies for PR ready, waiting on human, and merged/closed. |

- **Security & Scrubbing**: Before lines leave the relay or webhook/GitHub bridges, API keys and tokens, full room join links (including any embedded invite token), and room IDs (both `room-…` and `hs_…`) are removed.
- **Private-Room Slack Sender Guard**: On private (`hs_…`) rooms, the relay checks Slack callers (`users.info`) and ignores workspace guests (`is_restricted`, `is_ultra_restricted`), Slack Connect strangers (`is_stranger`), deactivated accounts (`deleted`), bots (`is_bot`), and external Slack Connect workspaces (`team_id` mismatch), failing closed if Slack lookup fails. Lookups are cached in memory for 5 minutes per connection, so an account deactivated or demoted in Slack can still post for up to 5 minutes.
- **Deduplication & Deadlines**: The relay acknowledges Slack event webhooks (`HTTP 200`) immediately to satisfy Slack's 3-second deadline, deduplicates `X-Slack-Retry-Num` and `event_id`, and avoids echoing bot or Slack-origin messages.
- **Attribution**: Messages originating from Slack are attributed in room chat as `slack:<handle>` (e.g. `slack:ganesh`), preventing impersonation of local room participants.

## 3. Controlling Agents from Slack

Full workspace members can control agents directly from Slack:
- **`stop` / `pause` / `halt`** (or `stop all`, `stop <AgentName>`): Pauses agents on their clients immediately.
- **`resume` / `unpause`** (or `resume all`, `resume <AgentName>`): Resumes paused agents.

## 4. Self-Hosted Fallback (`slack start`)

If you run your own private relay or prefer running a dedicated local bridge process on your machine, use `slack start`:

### Setup Steps:
1. Create a Slack app using [`slack-app-manifest-inbound.json`](../slack-app-manifest-inbound.json) with Socket Mode enabled.
2. Under **Basic Information → App-Level Tokens**, create an app token with `connections:write` scope (`SLACK_APP_TOKEN=xapp-…`).
3. Under **OAuth & Permissions**, copy `SLACK_BOT_TOKEN=xoxb-…`.
4. Invite `@Hivecode` to your channel (`/invite @Hivecode`).
5. Run the bridge:

**macOS / Linux:**
```bash
SLACK_BOT_TOKEN=xoxb-… SLACK_APP_TOKEN=xapp-… npx -y hivecode-mcp@latest slack start "wss://relay|room-…" --channel C0123456789
```

**Windows (PowerShell):**
```powershell
$env:SLACK_BOT_TOKEN="xoxb-…"
$env:SLACK_APP_TOKEN="xapp-…"
npx -y hivecode-mcp@latest slack start "wss://relay|room-…" --channel C0123456789
```

### Preflight Check (`slack check`)
You can test your tokens, channel permissions, and Socket Mode connectivity anytime:
```bash
SLACK_BOT_TOKEN=xoxb-… npx -y hivecode-mcp@latest slack check --channel C0123456789
```

## 5. Relay Owners: Enabling One-Link Slack Setup

To let users connect rooms with a single link (`slack connect` with no tokens or per-room apps), create one shared Slack app for your relay and set its OAuth credentials in the relay's environment.

### Step 1: Generate the Shared Slack App Manifest
Run `slack app-manifest` with your relay's public HTTPS URL:
```bash
npx -y hivecode-mcp@latest slack app-manifest "https://your-relay.example.com"
```
Create the app at [api.slack.com/apps](https://api.slack.com/apps) → **Create New App** → **From a manifest** → **JSON** tab, and paste the printed JSON.

It configures:
- **Bot Scopes**: `chat:write`, `channels:history`, `groups:history`, `users:read`, `channels:read`, `groups:read`, `channels:join`, `incoming-webhook`
- **OAuth Redirect URL**: `https://<your-relay>/slack/oauth/callback`
- **Event Subscriptions Request URL**: `https://<your-relay>/slack/events`
- **Bot Events**: `message.channels`, `message.groups`, `member_joined_channel`, `member_left_channel`, `channel_left`, `group_left`, `app_uninstalled`, `tokens_revoked`

### Step 2: Enable Public Distribution (No Marketplace Listing Required)
In your Slack app settings, open **Manage Distribution** → **Share Your App with Other Workspaces** and click **Activate Public Distribution** (all checklist items must be green, including HTTPS redirect and Events URLs).
- **No Slack Marketplace review is required:** external workspaces can install directly via your relay's OAuth link (Slack displays a standard unreviewed-app warning banner on the consent screen).
- **Workspace & rate notes:** some workspaces require admin approval or allow Marketplace-only apps, and Free workspaces cap total installed apps at 10. Slack's Tier 1 non-Marketplace cap applies only to `conversations.history` / `conversations.replies` — the relay uses Events API push plus `oauth.v2.access`, `auth.test`, `conversations.info`, `conversations.join`, `users.info`, and `chat.postMessage`.
- **Automatic cleanup:** if the user who installed the app leaves that workspace or becomes a guest, Slack auto-uninstalls the app and sends `app_uninstalled`, which the relay handles automatically.

### Step 3: Set Relay Environment Variables
From **Basic Information → App Credentials** in Slack, copy your app credentials into the relay environment:
- `HIVE_SLACK_KEY` — Any long random string used to derive the 32-byte `AES-256-GCM` encryption key for stored bot tokens (`Q660` if missing). **Never change it afterwards** — changing the key makes every stored Slack connection unreadable.
- `HIVE_SLACK_CLIENT_ID` — Shared Slack app Client ID.
- `HIVE_SLACK_CLIENT_SECRET` — Shared Slack app Client Secret (never leaves the relay; used only in server-to-server `oauth.v2.access` exchange).
- `HIVE_SLACK_APP_SECRET` — Shared Slack app Signing Secret (verifies `/slack/events` signatures).
- `HIVE_PUBLIC_URL` *(optional when `RENDER_EXTERNAL_URL` is set)* — Public HTTPS origin of the relay used to build install links and OAuth `redirect_uri`.

Then **restart or redeploy the relay** so the new environment variables take effect. *(If only `HIVE_SLACK_KEY` is set, one-link setup returns `Q669` and users can connect via `slack connect --manifest`.)*

## 6. Troubleshooting Reference

For complete error explanations and remedies, refer to [`docs/TROUBLESHOOTING.md`](TROUBLESHOOTING.md).

| Code | Component | Cause & Remedy |
| :--- | :--- | :--- |
| **`Q660`** | Relay | `HIVE_SLACK_KEY` encryption key is not configured on the relay (HTTP 503). Set `HIVE_SLACK_KEY` to any long random string on the relay server and never change it afterwards. |
| **`Q661`** | Relay / CLI | Connection ID is unknown or expired (24-hour unfinished TTL). Re-run `slack connect`. |
| **`Q662`** | CLI / Relay | Slack rejected the bot token (`auth.test` failed). Ensure token begins with `xoxb-` and the app is installed. |
| **`Q663`** | Relay | Bad Slack signature, timestamp outside 5-minute replay window, unauthorized disconnect, or manifest takeover attempt on a one-link connection (HTTP 401). |
| **`Q664`** | Relay | Bot is not in the channel. In Slack, run `/invite @Hivecode` in the target channel. |
| **`Q665`** | CLI | Invalid room join link syntax or invalid relay URL provided to `slack connect`, `slack status`, `slack disconnect`, or `slack app-manifest`. |
| **`Q666`** | CLI | Network failure reaching relay HTTP endpoint (behind `HTTPS_PROXY` on Node 22.21+, set `NODE_USE_ENV_PROXY=1`). |
| **`Q667`** | CLI | Required `SLACK_BOT_TOKEN` or `SLACK_SIGNING_SECRET` was not provided (`--manifest` connect or secret-authenticated `slack disconnect`). |
| **`Q668`** | CLI | Bot is in no channel (run `/invite @Hivecode`), or multiple channels without `--channel` in non-interactive mode. |
| **`Q669`** | Relay / CLI | One-link Slack setup is disabled on this relay (`HIVE_SLACK_CLIENT_ID`, `HIVE_SLACK_CLIENT_SECRET`, or `HIVE_SLACK_APP_SECRET` missing). Use `--manifest` or ask the relay owner to configure the shared app. |
| **`Q670`** | Relay | Selected Slack channel is already connected to another Hivecode room. Disconnect the existing bridge or select another channel. |
| **`Q671`** | Relay | Direct Messages (`D…`) and unsupported conversations cannot be bridged. Pick a public or private Slack channel. |
| **`Q672`** | Relay | Slack OAuth was cancelled, code/state was invalid, workspace team info was missing, or token exchange failed. Open the install link again and approve in a single workspace. |
| **`Q673`** | CLI | Timed out waiting for Slack OAuth approval on the install link. Open the link in a browser (within 24 hours) or run with `--no-wait` and check `slack status`. |
| **`Q674`** | Relay | Private (`hs_…`) room `slack connect` / `slack list` needs a token from the host or an invited maintainer (`401`), or `slack list` was called on an open room (`400`). Run on the host's or invited maintainer's machine (with its invite in `~/.hivecode/tokens`). |
| **`Q675`** | Relay | Only the host or a maintainer the host invited (`admin` / `maintainer`) may attach or list Slack channels (`403`), because everyone in the channel sees room chat. |
| **`Q630`** | `slack start` | `SLACK_BOT_TOKEN` missing or revoked. |
| **`Q631`** | `slack start` | Bot not invited to `--channel`. Run `/invite @Hivecode`. |
| **`Q632`** | `slack start` | Another bridge with the same name is already running in this room. |
| **`Q634`** | `slack start` | Missing `SLACK_APP_TOKEN` (`xapp-…`) or required scopes for Socket Mode. |
| **`Q635`** | `slack start` | Multiple active processes sharing the same `SLACK_APP_TOKEN`. |
