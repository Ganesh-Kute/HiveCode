GitHub watcher

The GitHub watcher turns labelled issues into pull requests without anyone watching a terminal. For a complete walkthrough from zero, see the Quickstart guide.

Prerequisites: Run npx -y hivecode-mcp@latest setup first (so your agent registers the tools), ensure you are logged in with gh auth login, and run commands inside your repository's local git clone. Without setup, the agent cannot join the room and will stop after spending a run of tokens.

Always test with a dry run first: 

npx -y hivecode-mcp@latest github start --agent "claude -p --output-format json --allowedTools Bash Edit Write Read Glob Grep mcp__hivecode" --dry-run

The dry run checks that gh is logged in, validates the agent command, verifies labels, and prints what would run without editing or pushing anything.

Once verified, start the watcher in your clone: 

npx -y hivecode-mcp@latest github start --agent "claude -p --output-format json --allowedTools Bash Edit Write Read Glob Grep mcp__hivecode"

Check current runs and status anytime: 

npx -y hivecode-mcp@latest github status

How the workflow runs

  1. Label an issue: Add the hivecode label to any issue.
  2. Agents work in a room: The watcher creates a branch, spins up a Hivecode room, and lets agents coordinate with file locks and structural merge.
  3. Tested PR submitted: A pull request is opened citing Closes #<number>, detailing what changed, and reporting test results, with one commit per agent.
  4. CI and human review: If CI fails or a human reviews the PR with comments, the agent receives the feedback and pushes fixes to the same PR. Plain comments are only routed if prefixed with /hivecode.
  5. Stopping or retrying: Remove the label or comment /hivecode stop to halt. Comment /hivecode retry to run again.

Slack integration

Hivecode connects to Slack to give your team live visibility and control over running agents, organizing work into one Slack thread per task or GitHub issue.

Create the Slack App

Choose the manifest that matches your workflow:

  • Outbound only (alerts and progress updates): Standard manifest with lowest privilege (chat:write, channels:read, groups:read). No message history and no public webhook URL or Socket Mode required.
  • Inbound controls (stop / retry from threads): Inbound manifest preconfigured with Socket Mode, message event subscriptions, and users:read. Required if you want full workspace members to reply stop or authorized users to reply retry.
  1. Open api.slack.com/apps and click Create New App → From a manifest.
  2. Select your workspace, switch to the JSON tab, and paste one of the manifests below:
    Option A: Outbound manifest (JSON — alerts only) 
    {
  "display_information": {
    "name": "Hivecode",
    "description": "One Slack thread per task or GitHub issue for Hivecode rooms.",
    "background_color": "#111318"
  },
  "features": {
    "bot_user": {
      "display_name": "Hivecode",
      "always_online": true
    }
  },
  "oauth_config": {
    "scopes": {
      "bot": [
        "chat:write",
        "channels:read",
        "groups:read"
      ]
    }
  },
  "settings": {
    "org_deploy_enabled": false,
    "socket_mode_enabled": false,
    "token_rotation_enabled": false
  }
}
    Option B: Inbound manifest (JSON — required for stop / retry with Socket Mode) 
    {
  "display_information": {
    "name": "Hivecode",
    "description": "One Slack thread per task or GitHub issue, with inbound stop and thread replies.",
    "background_color": "#111318"
  },
  "features": {
    "bot_user": {
      "display_name": "Hivecode",
      "always_online": true
    }
  },
  "oauth_config": {
    "scopes": {
      "bot": [
        "chat:write",
        "channels:read",
        "groups:read",
        "channels:history",
        "groups:history",
        "users:read"
      ]
    }
  },
  "settings": {
    "event_subscriptions": {
      "bot_events": [
        "message.channels",
        "message.groups"
      ]
    },
    "org_deploy_enabled": false,
    "socket_mode_enabled": true,
    "token_rotation_enabled": false
  }
}
  3. Click Next → Create, then click Install to Workspace and Allow.
  4. Under OAuth & Permissions in the left sidebar, copy the Bot User OAuth Token (starts with xoxb-).
  5. For in-thread controls (stop / retry): Ensure you selected Option B (the inbound manifest above). Under Basic Information → App-Level Tokens, click Generate Token and Scopes, name it socket-mode, add scope connections:write, and copy the token (starts with xapp-).
  6. Invite the bot & copy IDs: In your channel, run /invite @Hivecode. Click the channel name → view channel details to copy the Channel ID (C…). For --slack-allow, click any user's profile → More (⋮) → Copy member ID (U…).

1. GitHub watcher with Slack threads

Pass --slack-channel to the GitHub watcher so every issue run opens a dedicated thread in your channel. To also enable stopping and retrying from Slack, set SLACK_APP_TOKEN (Socket Mode, so no public URL) and pass --slack-allow:

Bash / Zsh (macOS / Linux):

export SLACK_BOT_TOKEN="xoxb-your-token"
export SLACK_APP_TOKEN="xapp-your-token"
npx -y hivecode-mcp@latest github start --agent "claude -p --output-format json --allowedTools Bash Edit Write Read Glob Grep mcp__hivecode" --slack-channel C12345678 --slack-allow U12345678

PowerShell (Windows):

$env:SLACK_BOT_TOKEN="xoxb-your-token"
$env:SLACK_APP_TOKEN="xapp-your-token"
npx -y hivecode-mcp@latest github start --agent 'claude -p --output-format json --allowedTools Bash Edit Write Read Glob Grep mcp__hivecode' --slack-channel C12345678 --slack-allow U12345678
  • Stopping from a thread: With SLACK_APP_TOKEN set, replying stop in an issue's Slack thread stops that issue. The watcher posts /hivecode stop (from Slack, by @handle) on the GitHub issue, and the normal command path acts on it, so GitHub keeps who asked.
  • Retrying (--slack-allow): retry works only for the Slack user IDs in --slack-allow U…,U…. Note that --slack-allow takes member IDs (U… from profile → More → Copy member ID, not display names), and requires SLACK_APP_TOKEN and --slack-channel (passing it without them refuses with error Q634).
  • Fail-safe permissions: Any full member may stop. Guests and other workspaces are refused. If Slack can't say who replied, stop still stops and says so afterwards.
  • Thread feedback: Also reported directly in the thread: "Pushed N commits to the pull request", and our own --test failing ("nothing was pushed").

2. Dedicated room bridge

To stream an existing Hivecode room into a Slack channel independently (with SLACK_BOT_TOKEN set as above). The room link ("wss://…|room-…") is printed by hive_join as the "invite link", or shown in the Control Room:

Preview with a dry run:

npx -y hivecode-mcp@latest slack start "wss://hivecode-relay.onrender.com|room-example" --channel C12345678 --dry-run

Start the bridge:

npx -y hivecode-mcp@latest slack start "wss://hivecode-relay.onrender.com|room-example" --channel C12345678 --allow U12345678

Inbound controls and stopping from Slack

  • Stopping is fail-safe: Any full workspace member can type stop all, stop, or stop <Agent> in a task's thread to halt agents immediately. Works on every Slack plan (including Free).
  • Owner permissions (--allow): Only user IDs specified in --allow can resume agents or send messages into the room. Refused actions are reported back in the thread.
  • Attribution: Messages sent from Slack arrive in the room attributed as slack:<handle>, preventing impersonation.
  • Honest updates: Channel posts and thread status updates are sent only after writes succeed on GitHub, avoiding false success signals.
