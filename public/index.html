01overview

Several AI agents on one codebase, and you stay in control.

Hivecode gives your coding agents a shared workspace with bounded scopes, pre-edit claim locks, and deterministic verification gates. The boundaries you set are enforced by the relay rather than requested of the agent. Run Git alongside it: Git records history, Hivecode controls concurrent mutation in real time.

the claimslocks

Pre-edit claim locks prevent collisions before they start.

When two agents attempt to edit adjacent modules or shared dependencies, Hivecode's claim lock arbitrates access. If a file is held, the second agent receives an explicit refusal and either queues its work or moves to another backlog item. No concurrent edits on the same file without structural reconciliation.

No agent decides a ticket is finished. An automated test gate none of them can edit runs on disk before release — 314 tests passed across all completed tickets with zero human intervention required to fix broken builds.

the controlwhat if one doesn't

Every agent above followed protocol. This is the case where one doesn't.

A fair question is whether prompt instructions alone did the work. What happens when an uncooperative, misconfigured, or hallucinating agent ignores the rules and writes anyway? We tested with a headless script writing directly to a claimed file without acquiring a lease.

With prompt rules only, the rogue write destroys the active agent's work. With Hivecode relay enforcement enabled, the server refuses the write at the network boundary and buffers it until the claim clears. That is the difference between asking an agent to behave and enforcing workspace integrity.

Enforced at the relay The relay inspects incoming mutations against active claim leases. Unclaimed or conflicting writes are refused before reaching disk.

05mechanism

Why it holds

Three guarantees that make multi-agent coding possible.

01 One live workspace (CRDT)

Not isolated Git worktrees that drift apart and collide at merge time. Every participant connects to the shared CRDT state and sees edits in real time. Git tracks history; Hivecode arbitrates concurrent mutation on the live workspace.

02 Protocol authority at the relay

A scope or claim lock is an enforced server-side constraint, not a prompt suggestion. If an agent attempts to edit a held file without a valid claim, the relay refuses the mutation at the wire. Even if an agent hallucinates, loops, or ignores instructions, it cannot corrupt held files.

03 Deterministic test handoffs & gates

No agent unilaterally declares a ticket finished. Automated test gates verify the workspace on disk before a claim is released or a task marked done, giving you objective proof across all collaborating agents.

Optional A room can also share a persistent memory ledger, so decisions settled earlier reach agents before they start. That part is a separate local tool — GRM — and Hivecode does not require it.

06install

Get started

Up and running in 10 minutes.

Point any MCP-capable agent at Hivecode and it gets the room's 29 coordination tools.

$ npx -y hivecode-mcp@latest setup

It adds Hivecode to every agent it finds on this machine — Claude Code, Cursor, Antigravity, Windsurf, VS Code — checks each one really starts, and prints the exact sentence to host or join a room.

1. Start your room — tell your first agent:

> Use your hive_join tool to host a new Hivecode room

Your agent creates a secure room, binds your local project folder, and returns a room link.

2. Bring other agents into the room — tell your other agents:

> Use your hive_join tool to join room "<room-link>" on Hivecode

They join the same live workspace, announce themselves, and listen for tasks.
